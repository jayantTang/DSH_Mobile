# TC-UI-105 发送后不再永久停在「等待开始」

对应改动：`已发送，等待开始` 永久挂住（`RenderedMessage.Status` 增加 `unconfirmed`、
`turn/end` 后宽限扫描、`restorePending` 不再自动重发）。

在**运行器新建的临时会话**里发一句话，核对三件事：

1. 发送后输入区清空、消息出现在时间线上（没有回归成"发不出去"）；
2. 等宿主回完一轮后，行状态不再停留在 `已发送，等待开始`，也没有变成
   `已发送，未确认，点击核对`（正常路径应当没有任何待处理徽标）；
3. 界面没有因此卡住：可以继续输入。

**边界**：`已发送，未确认，点击核对` 这条分支要宿主撤单才会出现（轮次以错误结束），
本用例不制造该场景，由 `SendStateTests` 与 `MessagePipelineTests` 的四条回归用例覆盖。

## 步骤

1. 打开临时会话转写
2. 点输入框
3. 输入示例消息
4. 点发送
5. 等待回完
6. 确认输入框可继续输入且没有待处理徽标
