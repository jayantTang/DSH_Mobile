# 性能基线

> 面向：实现者 · 状态：draft（基线未建立）

性能不以固定秒数起步，也不和功能验收混在一起。先定义旅程与测量口径，测当前基线，再由基线确定回归阈值。

## 不计入的项

- 不把 XCUITest 步骤耗时当产品指标：手势与截图本身有自动化开销。
- 不把整文件下载塞进“首屏”：下载单独看吞吐、续传和完整性。
- 不用模拟器性能代替真机基线；模拟器只做功能冒烟。

## 场景与起止点

| 场景 | 起点 | 终点 | 指标 |
|---|---|---|---|
| 会话列表首屏 | 请求发出 | 内容可见且可操作 | 毫秒 p50/p95 |
| 文本预览首屏 | 请求发出 | 第一页可见 | 毫秒 p50/p95 |
| 图片预览首屏 | 请求发出 | 缩略图或首图可见 | 毫秒 p50/p95 |
| 发送回显 | 点发送 | 本地出现用户消息 | 毫秒 p50/p95 |
| 重连恢复 | 网络恢复或回前台 | 可发送且状态已对齐 | 毫秒 p50/p95 |
| 长行滚动 | 开始滑动 | 到行尾 | 掉帧、长任务、是否可达 |
| 文件下载 | 开始下载 | 完成或失败 | 吞吐、续传、字节完整性 |
| 大文件内存 | 打开 | 稳定显示 | 峰值内存 |

## 基线方法

1. 固定构建、真机型号、iOS 版本、网络档位与数据规模；记录中转位置与是否同一局域网。
2. 冷启动、热启动分开；每个场景至少 30 次；去掉首次预热和明显环境异常。
3. 报告 p50、p95、最大值，不报单次最好值；同时记录失败率和环境异常。
4. 应用内用 signpost/埋点标出起止点；网络与服务端耗时能分开就分开。
5. 至少覆盖最低支持机型与当前主力机型；网络覆盖 Wi-Fi、4G/5G、弱网。

## 阈值

- 硬门槛：任务不可用，例如首屏空白、滚动不可达、发送无回显。
- 回归阈值：p95 不超过基线 +20% 或 +100 ms，取更宽者；日常门禁。
- 观察阈值：p95 超过基线 +50% 只告警，不阻断。
- 基线未稳定前只记录，不设硬门禁；阈值需 owner 确认后启用。

## 软阈值

按本轮基线 p95 +20% 暂定：会话列表 p95 ≤ 3113 ms，文本预览 p95 ≤ 2937 ms；发送本地回显目标 ≤100 ms。

这两个数只作软阈值：当前重复运行会把会话 p95 推到 4.4 s，说明设备热/系统负载尚未受控。启用硬门禁前必须冷却后重采 30 次，并确认长尾不再随运行次数上升。

## 基线报告字段

`场景 / 设备 / iOS / 网络 / 构建 / 数据规模 / 样本数 / p50 / p95 / 最大 / 失败率 / 测量日期`。

当前没有发布级基线；`SR-08.05` 不再使用 2 秒占位。

## 初始基线（仅参考，3 次）

2026-11-14，DSH-Test 仿真器（iPhone 17，iOS 27.0），公共中转，构建含 `PerformanceTrace` 埋点。

| 场景 | 样本 | p50 | p95 | 说明 |
|---|---:|---:|---:|---|
| 会话列表首屏 | 3 | 847 ms | 1186 ms | 冷启动到列表可用 |
| 文本预览首屏 | 3 | 123 ms | 284 ms | `long-line` 夹具 |
| 发送回显 | 3 | 0 ms | 0 ms | 目前只测到本地入队，屏幕渲染未单独计，需补 |

样本量不足，且是仿真器；这张表只证明埋点与采集链路可用，不作为发布门禁。

## 真机初始基线（2026-11-14）

iPhone 15（iPhone15,4），iOS 27.0.1，公共中转，Debug 构建；测试通过 Xcode UI 测试在真机启动 App 并读取 App 容器内的 `performance.log`。

| 场景 | 样本 | p50 | p95 | 说明 |
|---|---:|---:|---:|---|
| 会话列表首屏 | 30 | 1639.5 ms | 2594 ms | 第一轮连续 30 次 |
| 文本预览首屏 | 34 | 886.5 ms | 2447.7 ms | 长行夹具 |
| 发送回显 | 0 | — | — | 真机尚未采集；目前只测本地入队 |

同一轮后续重复启动时，会话首屏 p95 升到约 4445 ms（最大 6159 ms），说明设备热/系统负载会显著影响结果；基线必须冷却后重测，不能把长尾当稳定值。

这仍是初始基线，不是发布门禁：样本来自 Debug 构建，文件预览只 26 次，发送未采。先固定“冷却后 30 次、同一构建、同一网络”的采集流程，再谈阈值。

## 原生 UI 指标

开发者设置里的卡顿/帧率 HUD 用来现场判断，不进入基线：它没有稳定采样口径，也不产出 p50/p95。自动化改用 Xcode 自带的 `XCTHitchMetric` 与 `XCTMemoryMetric`，直接进测试结果。

`PerformanceBaselineTests.testLongTextScrollHitches` 在 iPhone 15、iOS 27.0.1 上打开 200k 字符单行夹具，做 2 次横向滑动：

- Hitches：0 次，hitch 总时长 0。
- 峰值物理内存：平均约 81,955 kB（样本 86,510 / 77,400 kB）。
- 常驻物理内存：约 77,171 kB，标准差 0.04%。

200k 单行没有出现 hitch，说明当前布局与滚动路径没有可测的卡顿；这组仍只覆盖 Debug 构建、单机与一次短滑动，不能替代 30 次基线。
