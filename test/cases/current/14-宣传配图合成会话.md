# TC-DEMO-01 宣传配图的合成会话截图

README 首屏那两张图出自这里，但它们不能来自真实会话——`docs/artifacts/screenshots/`
之所以不入库，就是因为真实截图带设备名、家目录与私有项目内容。这一条用例截的是
**合成会话**。

## 这条用例的特殊之处

- **它不验证产品功能**，只产出可发布的图。功能核对是 `TC-UI-01` 的事。
- **它的会话是造出来的**：`node scripts/dev/demo-session.mjs` 写一个虚构的小项目
  （`feeds`：拉 RSS、过滤已读、按时间排序），故意植入一个 bug，再让真实的一轮 agent
  把它修掉。所以转写里的流式输出、工具调用、测试输出都是真的，只有**内容**是编的。
- **`会话:` 是必填的**，不能靠 runner 挑：runner 的挑法是「历史最丰富的会话」，
  那会挑到用户的真实会话上——正是这一条要避免的事。
- **两处必须脱敏**，否则图不能发：
  - 设置页用 `-DSHDemoMode` 启动，把中转地址与主机主目录换成占位符（`SettingsView.masked`）；
  - 合成项目放在 `/tmp/dsh-mobile-demo`，因为 agent 会把绝对路径回显到转写里，
    放在家目录下每张工具卡片都会印出作者的用户名。
- 入库的两张图在 `docs/artifacts/demo/`（与 `screenshots/` 相反，那是**入库**目录）。

## 步骤

1. 连接本机 DSH，进入会话列表，截图留证。

2. 确认列表页工具栏的两个入口都在：连接管理、设置。

3. 打开合成会话的转写，截图留证。

4. 确认转写的开头在画面里：用户提问、工具的调用卡片。

   > 转写页在模拟器里滚不动（见 `.steps` 末尾），所以这张图拍的是首屏，
   > 看不到最终答复。要拍到答复得先让这个容器能滚。

5. 打开工作区文件页，确认它落在合成会话的工作区上（这张图只作核对，不入 README）。

6. 打开设置页（中转连接，`-DSHDemoMode`），截图留证。

## 说明

- 执行指令在同名的 `.steps` 文件里，本文件只描述用例本身。
- 生成会话：`node scripts/dev/demo-session.mjs`（打印会话 id，把它填进本文件的 `会话:`）；
  用完 `node scripts/dev/demo-session.mjs --cleanup-all` 清掉。
- 必须 `DSH_CONNECT=relay` 跑：设置页那张要的是「已配对设备」那一段，只有中转通道才有。
- 图片的取舍、排版与压缩口径见 `docs/artifacts/demo/README.md`。
