# TC-CHAT-01 键盘弹出后会话不跳白

用户报的现象：打开键盘或打字时，上方会话内容消失变白，往下拉才恢复。

## 为什么会跳白（这一版修复的依据）

键盘改变的是 **safe area 高度**，`ScrollView` 的内容偏移随之被重新计算；而会话是
`LazyVStack`，它按"可见矩形"决定哪些行存在。偏移一变、可见矩形一挪，已渲染的行可能
被回收，新的可见区间却指向**还没渲染的空位**——画面就是一片空白，随手往下拉一下触发
新的布局才恢复。

所以修复不是"改样式"，而是**在键盘可见性变化之后、动画结束时，把视口重新钉回底部
锚点**，迫使 `LazyVStack` 按新视口重建可见行。实现见
`ios/DSHMobile/DSHMobile/Support/KeyboardVisibility.swift` 与 `ChatView.repinAfterViewportChange`。

## 步骤

1. 连接本机 DSH，进入临时会话的转写（空会话）。

2. 点输入框让键盘弹出，截图留证。

3. 确认转写仍在。

4. 输入一条会让电脑端真跑一轮的消息（明确要求不要调用工具）。

5. 发送。

6. 等 host 开始这一轮（「已发送，等待电脑端开始…」消失），截图留证。

7. 确认转写仍在。

8. 在流式输出过程中打字，截图留证。

9. 确认输入框仍在。

10. 等这一轮结束（运行状态点消失），截图留证。

## 说明


- 会话用 `scripts/dev/demo-session.mjs` 造（与 TC-DEMO-01 同一个），内容可控、可重复。
- **只覆盖"跟随时"**：仿真器里无法对转写页做元素手势滑动，所以"回看历史时弹键盘"
  这条路径需要人眼看一次（那一路由 `isFollowing == false` 保护，不会把读者拽回底部）。
- 四步都能看到输入框上方有消息气泡，才算通过；只要有一张是"空白 + 键盘"，就是不通过。
- **已知不足**：`等待消失 id:chat.running` 用来等这一轮结束，但演示用的提示词只让 host
  跑了 1.4 秒（回答被截断，模型直接收尾），所以"长时间持续流入"这条路径没有被真正压到。
  要压它得让回复更长（例如让它逐行输出几十行），下一次改这条用例时补上。
