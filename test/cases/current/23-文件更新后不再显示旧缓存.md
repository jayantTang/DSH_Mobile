# TC-MOB-23 电脑上的文件更新后不再显示旧缓存

用户报的现象：在电脑上重新渲染过的视频，手机上点开还是旧的。原因是缓存只在「路径」上
判活——已经下载完成的文件，同一会话里再打开就直接用本地那份，从不问主机「这还是同一个
文件吗」。现在每次打开都先 `stat` 一次，主机的 version 变了就丢掉旧副本重新下。

## 覆盖与不覆盖

- 覆盖：下载完成后**同一次会话内**再次打开同一个文件——revalidate 先问主机版本；版本一致时
  直接用本地副本（不重复下载），版本不一致时丢弃旧副本、重新下载，并在状态条说明原因。
- 不覆盖：真实的重渲染（用例跑的时候没有人在改电脑上的文件），所以第二个打开由 DEBUG 钩子
  `-DSHSimulateRemoteChange` 让主机那次 `stat` 报出不同的 version——**版本号是注入的，
  之后的丢弃、重新下载、界面文案都是真实代码路径**；主机真的换了版本时的行为由
  `attemptDownload` 里既有的「按版本分目录」保证，并在 TC-MOB-19 里跑过。
- 夹具：`/tmp/dsh-git-demo`（setup.sh 生成，根目录 `附件.bin` 固定 300000 字节）。

## 步骤

1. 打开工作区文件页
2. 点开根目录的 附件.bin：等它下载完
3. 截图留证（首次下载完成的状态条，字节数 300000）
4. 关闭阅读页，回到文件列表
5. 再点开同一个文件：这次主机报的版本与本地副本不同，重新下载并在完成态说明「已按电脑上的新版本重新读取」
6. 确认它仍然处于可分享状态（没有停在失败或停在半路）
7. 截图留证（刷新后的状态条）
8. 关掉再打开第三次：钩子已用尽，这次应当是普通缓存命中——不再重下
9. 确认那句「已按电脑上的新版本重新读取」消失（说明它是这一次刷新的说明，不是常驻文案）
