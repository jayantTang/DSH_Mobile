# TC-CHAT-02 打开长会话落在最底部

用户报的现象：首次打开会话时停在"底部再上一段的中间"，要手动往下拉才到最后。

## 为什么会停在中间

打开会话时的锚定**只做一次**：把最后一条用户消息放到视口顶部，让回答在它下面读。
但长会话的首屏内容是分批折入的——锚定那一刻内容还没折完，锚点落在"当时的底部"，
后续折入的内容把它推到中间；而 `anchoredSessionId` 一经写入就不再重复锚定，
于是这个错误位置被一直保留。

修复见 `ChatView.repinAfterContentChange`：内容变化后**立即钉一次**（多数情况下这一下就
生效），再**延迟 150ms 钉一次**——因为 `LazyVStack` 的行高是在折入过程中被修正的，修正会
改变内容总高，系统的底部锚定因此会停在半路。两次都只在 `isFollowing`（读者没往上翻）时
执行，且延迟那次每次内容变化都取消重排，所以不会堆积（上一版 5 次重试 + 隐藏转写造成过
"变慢、二次打开卡住"，已回退）。

同时删掉了"打开时把最后一条用户消息锚到顶部"的逻辑：它与系统的底部锚定打架，也是
"停在半路"的来源之一。

第 2、3 两张截图逐字节相同，才算没有"先露中段再跳"。

## 步骤

1. 连接本机 DSH（进入会话列表）。

2. 滚动到未分组分组。

3. 展开该分组（会话行才会出现）。

4. 点会话行进入转写（**应用内**，首次打开）。

5. 立刻断言收尾标记 ZQ7X4P 在屏幕上。

6. 截图留证。

7. 点「返回」退回会话列表。

8. 滚动到同一行会话。

9. 再点该行进入转写（**应用内**二次进入）。

10. 立刻断言收尾标记在屏幕上（这一条覆盖用户报的"二次进入"）。

11. 截图留证。

## 说明

> 真机确认（2026-09-18，构建 20260918.1109）：首次打开与二次进入都直接停在底部，用户确认问题解决。
> 注意这条结论来自真机：二次进入的"中部跳底"在仿真器里复现不出来（见 report openpin-fix 的声明）。


- **判据是"只有末行才有的标记在不在屏幕上"**：演示会话的最后一行由提示词要求写成
  `ZQ7X4P`，且提示词里刻意把它拆成两段说（`ZQ7` + `X4P`），
  所以完整标记只可能出现在回答末尾——"看得见它"等价于"滚到底了"。
  前两版判据都被实测证伪：用「回到底部」按钮不在 → 出现"按钮不在、画面停在中段"的假通过；
  用「未提交」这类中文短语 → 它在转写中段也出现过，同样假通过。
- 会话用 `scripts/dev/demo-session.mjs` 造：提示词明确要求"只改一个文件、三句话讲清
  根因"，所以回答长到会超出首屏，符合"长会话"这个前提。
- 两次打开都要在底部：第一次覆盖"首屏分批折入"，第二次覆盖"重进"。
