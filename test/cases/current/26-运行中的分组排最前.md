# TC-MOB-26 运行中的分组排最前

用户的要求：有正在运行会话的分组排到最前；未分组与已归档仍在最后；每行要能一眼看出「运行中 /
运行完还没看 / 看过了」。手机端**有意不再镜像桌面的工作区顺序**。

规则（实现见 `SessionRowState` 与 `SessionListModel`）：
- 组：有运行中会话的组在前，两部分各自按最近活动排；
- 组内：运行中 → 未查看 → 已查看 三个桶，桶内按最近活动排；空会话在最后；
- 「未查看」= 非运行、非空、且 `updatedAt` 晚于本机上次打开它的时间；第一次在列表里见到它时
  以当时的 `updatedAt` 作为基线（否则配对后会整屏未查看）。

## 覆盖与不覆盖

- 覆盖：运行中的会话在退回列表时**就在屏幕内**（排序的结果），行上有 `session.state.running`
  与「运行中」。
- **不覆盖**（如实记下，别当成测过）：未查看/已查看两态在这次 UI 里没有断言。原因有两条：
  一是列表里永远有一条正在跑的会话（就是执行本用例的那条），`text:运行中` 无法归因到某一行；
  二是要让另一条会话稳定地停在「跑完但没看」这一态，需要控制它何时结束，而这一轮由真实 agent
  执行、耗时不可控（试过 sleep 提示词与固定等待，都会偶发）。
  这两态由 `SessionRowStateTests`（7 条，含「同刻算已读」「更早算已读」「首次见到算已读」）与
  `SessionListOrderTests`（6 条，含「运行中→未查看→已查看→空会话」与并列按最近活动）覆盖；
  另外加了一道 `SessionViewLog` 持久化，代码审查确认。
- 不覆盖：多组同时运行时的相对顺序（清单里另一条在跑的是执行本用例的会话本身，环境里消不掉）；
  「看过了」在 App 重启后仍然记得（`UserDefaults` 持久化，靠代码审查）；子代理行跟随父行（未制造子代理）。
- 一处如实说明：第 8 步的「运行中」文案无法归因到**某一行**（环境里总有另一条在跑的会话），
  所以「这一行」的归属由第 12 步的未查看标识来证明——那个标识只可能来自本用例的会话。
- 「已查看」这一步只断言行还在 + 截图目视，**不做**「屏幕上没有『已完成』」的全局断言：
  列表里还可能有别的未查看会话（电脑上跑过、这台手机没看过），那种断言会偶发；已查看这一态
  由 `SessionRowStateTests` 的两条单测（同刻算已读、更早算已读）覆盖。

## 步骤

1. 连接本机 DSH，看到会话列表
2. 滚到运行器建的临时会话那一行
3. 点它进入转写
4. 点输入框
5. 输入「请只回复两个字：收到」
6. 发送
7. 退回列表
8. 确认这一行仍在屏幕内，且列表里有「运行中」
9. 截图留证：运行中的样子
