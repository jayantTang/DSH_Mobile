# Agent Team · 多 Agent 开发管线

一套**程序化编排**的软件开发管线：三个固定角色，独立会话、文件交接、异厂验证。
编排层只传递信息，不掺杂自己意见、不替 owner 做决定。

## 三个角色

| 角色 | 模型 | 负责 |
|---|---|---|
| 软件架构师 | **kimi-k3** | 梳理代码、分析架构与坏味道/bug；输出设计、修改方案、修改项划分、修改指导；收尾做最终评审 |
| 软件开发工程师 | **deepseek-v4.1-flash** | 依据修改方案逐项改代码、自测，如实报告 |
| 软件测试工程师 | **glm-5.3** | 制定测试计划、执行测试、出测试报告（与开发异厂） |

## 管线

```
需求
 → ① 架构师设计（方案 + 修改项 + 修改指导 + 测试关注点 + 给 owner 的人话影响说明）
 → [GATE-0 owner 拍板]
 → ② 开发逐项改代码 + 自测
 → ③ 测试工程师（异厂）制定计划、测试、出报告
 → ④ 架构师评审：不通过打回开发/测试/设计；通过则汇总向 owner 汇报答疑
 → [GATE-1 owner 决策]
```

## 规则

- **角色之间只传文件，不传对话**；产物落 `runs/<id>/artifacts/`
- 每个角色一次性独立会话；架构师 ① 与 ④ 是两次独立调用
- 开发发现指导做不到/矛盾 → 打回架构师，不临场发挥
- 面向 owner **讲人话**；需要决策的用**多选题**（给选项与代价）
- 编排层（主会话）边界：只推进与传递，不补充技术判断、不改写结论、不替 owner 选择

## 文件

- `pipeline.yaml` —— 管线唯一事实来源（阶段、交接、门禁、汇报口径）
- `archive/v1-heavy/` —— 早期重型 6 角色试验（已归档，留作复盘）
- `runs/` —— 每次运行的记录与产物

## 用法

对编排层说一个真实需求即可，管线按 `pipeline.yaml` 推进；owner 只在 GATE-0 / GATE-1 介入。
