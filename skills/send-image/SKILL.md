# 发送图片到会话

**核心能力**：把一张图片放进对话，用户在他的 DSH 客户端里**直接看到图**，可点开放大。

## 为什么需要这个 skill

DSH 的模型适配器声明**纯文本输出**——agent 自己无法在回答里发出图片。
附件服务是**只读**的，也不能由客户端写入。

**图片进入会话的唯一通道是 prompt**：Host 会把内联的图片字节**提升为持久附件**，
并顺带做归一化（格式转换、压缩、去重）。这个 skill 就是走这条通道，
把图发到**当前正在对话的这个会话**里。

## 用法

```bash
S=~/.dsh/skills/send-image/send-image.mjs

node $S --screenshot                                  # 截整屏发出去
node $S --file ~/Desktop/chart.png                    # 发送指定图片
node $S --file ./out/render.png --caption "渲染结果"   # 带说明
node $S --clipboard                                   # 发送剪贴板里的图
```

**会话是自动确定的**——脚本读取 `$DSH_SESSION_ID`（Harness 注入），不需要你传 session id。

## 什么时候用它

| 场景 | 做法 |
|---|---|
| 用户要看界面/渲染效果 | `--file` 指向上一步生成的截图或产物 |
| 用户要"看一下现在屏幕" | `--screenshot` |
| 系统弹窗/报错需要目视确认 | `--screenshot`（先把窗口切到前台） |
| 用户给了图要你转发 | `--file <他给的路径>` |

## 关键约定

- **先确认图片存在且非空**：脚本会拒绝空文件和超过 24 MB 的文件。截图后如果命令
  返回非零，不要假装成功。
- **发送后要说明**：图片到达后，用一句话说清这是什么，不要让用户猜。
- **不要滥用**：能用文字说清的就别发图。发图是为了让用户**目视确认**，
  不是替代文字结论。
- **截图会包含屏幕上的一切**：发送前想一想画面上有没有不该发的私密内容，
  必要时先切到目标窗口。
- **图片是异步到达的**：`--screenshot` 之后不要把"图片已送达"当成用户已经看过；
  他可能不在电脑前。

## 依赖

- `screencapture`（macOS 自带）
- `pngpaste`（仅 `--clipboard` 需要）：`brew install pngpaste`
- 屏幕录制授权（仅 `--screenshot` 需要）：macOS 把它给**应用**，不是给脚本。
  若报 `could not create image from display`，是 DSH.app 没拿到授权 —— 在
  「系统设置 → 隐私与安全性 → 屏幕录制」里勾选 DSH，然后**退出并重新打开 DSH.app**
  （macOS 只把新权限交给重新启动后的进程）。DSH.app 菜单「DSH → 屏幕录制权限…」可以直接查。
