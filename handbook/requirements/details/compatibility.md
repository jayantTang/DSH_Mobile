# 兼容细节

## SR-10.01 能力探测与降级

- 能力词表的单一来源是 `docs/relay-contract.json` 的 `capabilities`；连接器的 `SERVER_CAPABILITIES` 与 App 的 `LinkHandshake.Capability` 与之逐字一致，由 `npm run check:contracts` 第 ⑤ 段守住。
- 「缺声明即降级」是单向判定：App 不推测未声明的能力，连接器不假设 App 会发某个方法。
- 降级只影响该能力对应的入口，不整页报错；缺能力不重试、不提示网络失败。
- 典型形态：`_link/*` 保留方法在旧连接器上会被转发到宿主并得到非 JSON 404；该形态说明缺能力，不是网络故障。新连接器对未知 `_link/*` 回 `link/unsupported`，不再转发。
- 新增保留方法的顺序：先加能力位与降级路径，再启用调用；两者同批发布。
- 能力位出现前的过渡版本用版本基线补判：图片变体的能力位是 `image-variants`（0.8.2 起声明），方法本身从 0.8.1 就有，所以 0.8.1 仍走变体路径。基线只写在 `ImageVariantSupport` 一处，版本读不出（空串、`git describe`）时按不支持处理。

## SR-10.02 中转向下兼容

- 协议版本由 `/healthz` 的 `version` 声明；不兼容变更提升该值并与连接器同批发布。
- 旧端冒烟范围：上一版本连接器与上一版本 App 连到新中转，跑连接、收发一条消息、传一个文件、提交一封信。
- 必达帧（`res` 与控制帧）不因背压被判可丢；排不下时按协议断开让客户端重连，不静默丢弃。

## SR-10.03 兼容缺口可验证

- 旧版本行为夹具取自 npm 上已发布的包（例如 `npm pack dsh-plugin-mobile-link@0.6.6`），不手写想象形态。
- 兼容决定在需求条目、变更记录与用例三处对齐；发布记录引用用例路径。
