# 产品定位

## 一句话

把电脑上的 DSH 会话接到 iPhone 与 iPad：原生 iOS 客户端、电脑侧连接器、可自建的公网中转。

## 目标用户

在电脑上使用 DSH 的个人用户与开发者。离开电脑后，仍需继续同一会话、处理挂起提问。

## 使用前提

- 电脑已安装并可运行 DSH（`dsh web`）。
- 连接器需要 Node.js 22 及以上。
- 自建中转需要一台有公网 IP 的主机与 Caddy。
- 手机通过 TestFlight 安装 App。

## 范围

关键行为与策略写在 `requirements.md`，本文只界定定位与范围：

- 连接：登记、配对、设备管理、传输（IR-01）。
- 会话：查看与继续、待答（IR-02）。
- 工作区：文件与 git 查看（IR-03）。
- 分发与更新：TestFlight、版本、发布（IR-04）。
- 反馈：提交、收件箱、回信（IR-05）。
- 设置：权限、凭据状态、缓存、版本（IR-06）。
- 客户端：iPhone/iPad 布局（IR-07）。
- 可靠性、安全与性能：重连一致性、文件完整性、撤销、密钥边界、性能预算、通知语义（IR-08）。
- 国际化与本地化：语言矩阵、端到端一致性、翻译流程、区域格式、自动化门禁、用户语言选择（IR-09）。
- 版本兼容：能力探测与降级、中转向下兼容、兼容缺口可验证（IR-10）。

## 非目标

- 不记录实现方案、接口与数据结构；这些随代码演进。
- 不承诺 `requirements.md` 未列出的能力。
